# QQQM 智能投资研究助手

**QQQM AI Investment Research Assistant** · 统一投资研究工作台

这是一个面向投资新手研究与学习的 QQQM 原型产品，尝试将个人交易账本、市场背景解释和预测复盘整合成可追溯的研究流程。它把旧版市场 Dashboard、持仓与网格回测、下一交易日预测、盘中走势、预测复盘、模型对比和多平台中文视频脚本导出放进**一个 Streamlit 入口和统一导航**，尽量复用原有代码和 SQLite 数据库，不再要求每个功能单独启动一套 Dashboard。

> 重要：这是研究与教学工具，不是自动交易系统。预测不是投资建议；模型每次更新都必须和简单基准做样本外对照，不会因为一天猜对就自动升级。

## 当前主导航（清爽演示版）

主侧边栏只保留四个核心页面：

1. **研究驾驶舱**：展示最近可用行情、行情日期、当前账号的持仓估值、价格曲线和近期已保存新闻。
2. **市场与持仓**：查看详细市场数据、AI 报告、个人交易账本与相关分析。
3. **预测情景**：查看下一交易日预测参考与历史价格情景。
4. **预测复盘**：检查已结算预测、误差指标和基准模型表现。

辅助/实验页面仍留在代码中，但不再显示在主导航里，避免演示时菜单过长。研究驾驶舱会明确显示本地行情日期；如果数据过期，请先更新数据或在演示中说明使用的是历史数据。它不代表实时行情。


## 1. 最简单的启动方法（Windows）

1. 解压整个项目到一个**固定的英文路径**，例如 `E:\Projects\QQQM_AI_Investment_Research_Assistant`。不要在压缩包内层继续套一个同名文件夹。
2. 把你自己原来的 `.env` 复制到项目根目录；如果没有，则复制 `.env.example` 并重命名为 `.env`，填写自己配置的数据源 / DeepSeek API Key。**新版压缩包不会包含私有 `.env`，不要把真实密钥发给别人或提交到 GitHub。**
3. 首选直接双击 `Start_QQQM_Assistant.bat`。它会通过 Windows Python Launcher 创建项目专用 `.venv`、安装 `requirements.txt`、执行一次数据同步/预测反馈工作流，再启动网页。第一次安装依赖需要联网；如果失败，先看终端显示的具体错误。
4. 浏览器打开 `http://localhost:8501`。第一次可以创建本地账号；如果保留了自己的 `data/users.db`，原来的本地账号也会保留。

也可以在 VS Code 终端使用 `.\Start_QQQM_Assistant.bat`。不要再用系统默认的 `python` 直接启动，因为部分 Windows 环境会优先指向 MSYS2 的 Python，那里可能没有 pip 或 Streamlit。若只输入 `python -m streamlit run dashboard.py`，会绕过启动时的数据同步；登录后研究驾驶舱也提供显式的一键同步操作。

### 项目打开之后

登录后默认进入“研究驾驶舱”，页面展示本地行情日期、最近可用收盘价、持仓估值、价格走势和近期新闻。左侧只保留演示最需要的四个入口：研究驾驶舱、市场与持仓、预测情景、预测复盘。

打开网页本身不会偷偷发起 API 请求。需要更新时，点击驾驶舱、预测情景或预测复盘页面上的**同步/重建按钮**；完整工作流会尝试同步行情、新闻和宏观数据、结算已有预测，并在行情日期变化或预测文件落后时生成最新预测。同步是否成功必须看日志、数据库最新日期和数据源字段，不以按钮点击成功为准。若 API 暂不可用，页面会把 2026-10-23 的公开网页校验快照明确标记出来，不会冒充为实时 API 数据。

## 2. 每日预测闭环怎么工作

1. 同步现有数据源允许获取的日线、盘中 K 线、新闻及可选宏观数据。
2. 只使用同一交易日事前保存的预测记录与真实行情做复盘，记录开盘、最高、最低、收盘和盘中路径误差；若找不到事前预测，不会事后补画一条线冒充原预测。
3. 将新结果写入历史评估数据；原有的日线与盘中候选模型仍按时间顺序进行评估。
4. 盘中路径流程生成新的预测快照，保留主路径、历史参考曲线和数据来源信息。
5. 只有预测目标日晚于最新实际行情日期时，才允许导出下一交易日的内容。内容输出为 HTML、Markdown 和 PNG；系统不会自动发布到微信公众号。

统一工作流日志在 `reports/unified_daily_workflow/`。盘中预测快照和历史存档在 `reports/intraday/`。视频脚本、纯口播稿、两张配图和 ZIP 在 `reports/video_scripts/YYYYMMDD/`。视频专用的未来走势情景状态写入 `reports/intraday/QQQM_video_forecast_latest.json`；原有模型快照和不可变历史归档保持独立，不会被视频回算参考冒充覆盖。每日成绩表和模型比较记录仍在 `reports/`。

## 3. 多平台视频脚本与配图

在“多平台视频脚本与配图”页面点击新版一键流程。它先刷新公开日线、分时和官方新闻，然后尝试结算同源历史前瞻记录、训练盘中岭回归候选和运行滚动回测，再生成适用于小红书、抖音、微信视频号、B站的中文口播稿、平台标题/简介和两张中文图。只有预测基准日、目标日和分时来源完全对齐的候选，才会作为机器学习主路径叠加到图二；否则图二会标为历史统计情景参考或暂不可用。口播稿约30–60秒，聚焦两张图、最多一句新闻背景和风险提示。

项目保存了用户提供的 **2026年10月20日已发布预测图**，见 `reports/intraday/archive/QQQM_2026-10-20_已发布预测图.png`。复盘该交易日时，程序会将此图中可读的开盘参考295.16美元、收盘参考294.55美元及从图像还原的橙色中位路径，与刷新取得的真实十五分钟蓝线叠加。原图中间点为图像坐标估读并按15分钟插值，误差只能作为近似对照；原图的±0.75%阴影带不是统计置信区间。原图、来源说明及还原后的数据均随项目保存。

重要规则：第一张复盘图只会使用同日事前保存的预测，或上述已发布图像的还原线。不会把事后回算出的路径冒充事前预测；若没有真实的完整分时行情，程序会明确显示数据暂不可用，不会用日线四个价格点拼接真实分时。

第一张图展示最近一个完整交易日的真实分时收盘走势，并叠加同日提前存档的预测曲线。如果没有保存当时的预测快照，程序只能在数据充足时画出“此前历史数据回算参考线”，并明确注明这不是当时发布的预测。第二张图根据此前完整交易日的十五分钟历史路径和隔夜开盘变化分布生成下一交易日情景；历史样本不足或行情未刷新时，会明确标记不可用。新闻会做中文概述，但不会仅凭新闻标题臆造价格方向。

独立的视频行情流程会依次尝试已配置的行情接口和免密公开行情接口，可能受网络、限流、套餐权限或数据服务变化影响。网络失败时会保留诊断信息；不会承诺任何环境下绝对无错误，也不会把旧日期说成最新数据。原有完整盘中学习、模型复盘流程仍使用项目原有数据源，若运行该流程仍遇到 Alpaca HTTP 401，需要检查 `.env` 中的 `ALPACA_API_KEY_ID` 与 `ALPACA_API_SECRET_KEY`，但不影响视频流程独立生成。

每份内容包含两张图：
- `01_上一完整交易日真实走势与预测对比.png`：将最近一个完整交易日的十五分钟真实分时收盘曲线，与同日存档预测或明确标注的历史回算参考线叠加。
- `02_下一交易日走势情景参考.png`：根据此前完整交易日的分时统计生成下一交易日参考路径和区间；没有新鲜行情或样本不足时，会显示中文说明，不会用旧曲线冒充未来。

输出目录为 `reports/video_scripts/YYYYMMDD/`，包括 Markdown/TXT 脚本、元数据和 ZIP。系统不会自动向任何平台发布。

若出现 Alpaca HTTP 401，请检查项目根目录 `.env` 中的 `ALPACA_API_KEY_ID` 与 `ALPACA_API_SECRET_KEY` 是否为同一组有效凭据。密钥鉴权失败无法靠 GUI 代码绕过；修复后再运行每日闭环。

## 4. 机器学习与模型升级规则

- 现有模型包括日线回归、基于历史盘中样本的路径估算和候选模型比较；K 线特征实验可在“模型学习与预测复盘”页面查看。
- 每次预测都应保存为不可覆盖的历史快照，随后用真实市场数据评估。
- 价格模型的 MAE / RMSE、方向判断和参考范围覆盖率应按时间顺序评估，并与简单基准比较。
- 不因单个交易日结果就改参数或替换主模型。只有候选方案在足够的样本外记录中持续优于当前模型，才应晋级。
- 日线数据不能证明 5 分钟价格路径准确。时间精度越细，越需要真实且一致来源的盘中 K 线；如果 API 没有权限或下载失败，程序应显示失败，而不是补造曲线。
- “模型学习与预测复盘”页面新增“运行滚动验证与晋级评估”。它会把训练 CSV 截止日之后、已经存在本地 SQLite 的最新日线追加到独立评估副本，不修改原始训练 CSV；随后运行扩展窗口回测、时间留出集 Champion–Challenger 对照和真实前瞻反馈门槛。
- 命令行也可运行：`python scripts/run_model_evaluation_suite.py`。输出为 `reports/model_lab/QQQM_model_evaluation_scorecard_latest.json` 及相应的模型、月度和区间明细。该流程只评估，不联网、不生成新交易指令、不更改生产模型。
- 晋级须同时查看历史时间留出集和真实前瞻反馈：实时同口径可比样本至少 30 条，候选 MAE 相对历史均值基准改善至少 5%，之后仍只进入人工复核，不自动替换。日线收益预测与十五分钟路径预测必须分别评估，不能把其中一个的成绩当作另一个的准确率。

## 5. 数据与密钥安全

- `.env` 存放私有 API Key，不能上传到公开仓库。
- `data/market_data.db`、`data/users.db`、`data/portfolio_transactions.csv` 和 `reports/` 可能包含个人持仓、交易记录、账户或研究档案。该压缩包用于你自己的本地项目恢复；**不要原样推送到公开 GitHub**。
- 发布前请创建一个干净的“代码部署副本”，不包含本地数据库、交易流水、个人报告和 API 密钥。
- 当前注册 / 登录是本机原型，账户存储在 SQLite 中，适合本机研究。它不是面向陌生人的生产级多用户身份系统。

## 6. 数据更新诊断与“生成视频是否等于训练模型”

统一入口新增“数据更新与系统诊断”页面。它只读取本机数据库和运行报告，分开显示日线交易日期、完整十五分钟数据日期、新闻发布时间、最后抓取时间、宏观数据、评估成绩单日期、密钥是否配置，以及上一轮流程失败在哪一步。点击“重新读取本地状态”会清理 Streamlit 本地缓存并重新读取文件，但不会联网。

**视频生成和机器学习分成两个步骤。** GUI 的新版主按钮会先尝试运行公开行情盘中学习闭环：刷新数据、用同源实际行情结算旧预测、用历史完整交易日重新拟合岭回归候选并做滚动回测，成功后再让视频生成器使用这次有效的新候选。若训练阶段因行情不可用或样本不足而失败，界面仍可尝试生成历史统计情景内容包，但必须明确标注它不是机器学习主路径。单独运行 `scripts/generate_video_script.py` 只负责生成内容，不训练模型。

要持续复盘和改进，需要在行情日期更新后分开执行：

1. “结算日线预测反馈并生成下一交易日候选”：使用当前本地日线，结算已到期日线预测、重新计算日线候选并保存新的前瞻记录。若日线仍落后于最近完整交易日，页面会禁用按钮以防生成目标日已经过去的预测。
2. “运行本地滚动验证与晋级评估”：比较简单基准与 Ridge 候选模型；只评估，不自动替换生产模型。
3. 新版视频页一键流程会运行 `scripts/run_public_intraday_learning_cycle.py`，尝试使用同源公开分时数据学习与复盘，不需要 Alpaca。若公开行情源未能提供最近完整交易日或至少 25 个完整交易日样本，学习步骤会失败并明确记录原因。原有“运行盘中学习流程”仍使用 Alpaca，需要 `.env` 中配置有效的 `ALPACA_API_KEY_ID` 与 `ALPACA_API_SECRET_KEY`。

盘中学习闭环状态中的 `model_training_performed: false` / `model_promotion_performed: false` 表示该次运行未标记为正式训练或自动晋级。成功同步后会结算旧记录、重建学习数据集、运行候选路径和回测；要认定模型变准，仍需看独立滚动验证、实时已结算样本数和候选晋级报告。

**完整交易日的分时校验更严格。** 当前健康检查要求常规交易时段至少 24 个十五分钟点，并覆盖 09:30 至 15:45；不再因为少数零散 K 线就显示“完整分时已更新”。

## 8. 常见故障

- **页面打不开**：看 PowerShell 终端是否有报错，先确认虚拟环境依赖安装完整。
- **第二张图显示历史统计而不是机器学习候选**：查看视频页的一键流程状态和 `reports/public_intraday_learning_cycle/latest_status.json`。只有公开行情刷新、历史预测结算、候选拟合与日期对齐都完成，图二才会画橙色机器学习主路径；否则显示历史统计参考或不可用。
- **新闻或宏观同步失败**：检查对应 API Key、配额和网络。可先关闭可选的新闻 / 宏观同步，再查看其他步骤的日志。
- **原有盘中学习闭环报 Alpaca HTTP 401**：检查 `ALPACA_API_KEY_ID` / `ALPACA_API_SECRET_KEY` 是否为同一组有效凭据。此项只影响高级学习流程，不影响独立的视频公开行情流程；如果公开行情也无法访问，请检查网络或数据服务限制。
- **公开部署**：请先阅读 `DEPLOYMENT.md`，不要把私有数据库和密钥上传。


## 视频输出与机器学习反馈（本次升级）

每次生成的视频内容固定保存在 `reports/video_scripts/YYYYMMDD/`，包含两张图、短口播稿、四个平台标题与简介、元数据和可分享 ZIP。标题/简介单独保存为 `视频标题与简介_直接复制发布.txt`，纯口播稿仍在 `每日视频口播稿_可直接照念.txt`。

生成的未来预测 JSON 另外归档在 `reports/video_scripts/forecast_archive/`，供之后审计和对账。训练反馈不依赖用户下载图片保存在哪里，而依赖当时不可变的预测 JSON/预测快照以及后续同一数据源的真实十五分钟行情。只有图片而没有原始预测点时，只能进行图像近似还原，不能算作精确机器学习反馈。

DeepSeek/OpenAI 类大语言模型适合提取财报、新闻事件、预期差异和风险情景，并输出可审计的结构化特征；精确价格路径仍应由时间序列/统计模型产生，再在滚动样本外测试中比较。大语言模型本身不能凭新闻标题可靠地“算出”下一日每个十五分钟的价格，不应把生成式文本当成训练后的量化预测。

## 新闻与财报特征研究实验（2026-10-22）

本版本新增 `scripts/run_news_earnings_walkforward_experiment.py`，用于在相同的扩展窗口样本外日期上比较 M0（行情特征）与 M1（行情+新闻特征），输出配对预测、MAE/RMSE、方向/平衡准确率、Brier Score、Log Loss 和配对 MAE 自助法区间。运行方式：

```bash
python scripts/audit_news_earnings_data.py
python scripts/run_news_earnings_walkforward_experiment.py
```

结果位于 `reports/research/`。当前数据库只有 40 条新闻、28 条已有分类，且这些分类均为文章发布后生成的回溯式文本编码；因此 M0/M1 结果只作探索，不代表当时实时可用的新闻策略。当前数据库未发现有可靠实际发布时间、EPS/营收一致预期及实际值的结构化财报表，M2/M3 明确阻断，不使用伪造或默认中性数据补齐。生产模型未更换。两张 2026-10-20 与 2026-10-22 历史图保存在 `reports/learning_materials/`。

### Point-in-time earnings feature ingestion

The research package includes `app/earnings_features.py` and a CSV contract at `data/templates/earnings_point_in_time_template.csv`. The validator rejects records whose availability timestamp predates the declared release timestamp, requires a source URL, preserves missing analyst consensus as missing, and provides as-of feature extraction. QQQM is an ETF: underlying constituent earnings must not be treated as direct QQQM earnings. To aggregate constituent events into ETF-level features, use historical point-in-time holdings weights. ### 最新研究进展：QQQM 成分股财报聚合

`app/earnings_features.py` 中的 `aggregate_constituent_features_asof()` 支持基于预测时点可知的 QQQM 成分股持仓快照，将底层公司的财报意外值和指引变化按权重聚合为 ETF 级特征。持仓快照需提供 `ticker, weight, available_at, source_url`，数据源若支持应额外提供 `snapshot_id`。无快照 ID 时按来源 URL 和时间间隔推断快照，避免把同一 UTC 日期的早晚两份导出混合；这只是保守回退，供应商原始快照 ID 仍然最好。未来快照会被排除，覆盖率低于 70% 时特征保留为缺失值。

新增持仓模板 `data/templates/holdings_point_in_time_template.csv` 和离线校验工具 `scripts/validate_earnings_holdings_import.py`。将真实数据分别放入 `data/earnings_point_in_time.csv`、`data/holdings_point_in_time.csv` 后，运行 `python scripts/validate_earnings_holdings_import.py` 检查必需字段、时间、来源链接、重复记录与快照权重合计。该工具只生成校验报告，不会把未经审核的数据写入生产数据库。当前项目没有可用的真实历史财报一致预期与历史持仓文件，因此 M2/M3 仍未完成真实回测，不能把合成测试结果当作真实市场验证。
